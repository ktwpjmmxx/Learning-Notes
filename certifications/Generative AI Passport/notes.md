**通常プロンプトとの違い**
ユーザープロンプト
　→ 利用者が毎回入力する指示文。「質問」「タスク依頼」「条件設定」など。
システムプロンプト
　→ 開発者やシステム側があらかじめ設定する指示。AIの「キャラクター」「トーン」「役割」「制限事項」を決める。
▪️観点
「システムプロンプトの役割は？」

「ユーザープロンプトとの違いは？」
→ ユーザーが直接入力するのはユーザープロンプト、開発側が内部で設定するのがシステムプロンプト。
「システムプロンプトを工夫すると何ができるか？」
→ 安定したトーン・一貫性のある応答が得られる。

## 補足：ファインチューニング

### 1. 基本の考え方
- **プレトレーニング（事前学習）**  
  大量のデータで一般的な知識を学習（例：BERTやGPT）。  
- **ファインチューニング（微調整）**  
  特定タスクや領域に合わせて追加学習。少量のデータでも有効。  

👉「大辞典を覚えたあと、自社マニュアルで仕上げる」イメージ。

### 2. 主な手法
1. **フル・ファインチューニング**  
   - モデル全体のパラメータを更新  
   - 精度は高いが計算コスト大  

2. **パラメータ効率化ファインチューニング（PEFT）**  
   - 一部のみ更新して効率化  
   - 代表例：  
     - **LoRA（Low-Rank Adaptation）**  
       重み行列を低次元近似して更新  
     - **Prefix Tuning / Prompt Tuning**  
       プロンプト部分だけ追加学習  ---

### 3. 活用例
- **分類タスク**：感情分析、ジャンル分類  
- **QA（質問応答）**：FAQ対応  
- **生成タスク**：レシピ、商品説明、自社文書対応  

### 4. 試験で押さえたいキーワード
- 事前学習済みモデルを **特定用途に最適化**  
- **部分的な微調整手法** によりコスト削減  
- 代表例は **LoRA / Prompt Tuning**

## 補足：ハルシネーション対策とファクトチェック

### 1. ハルシネーション
- **定義**：AIが「もっともらしいが事実ではない情報」を生成する現象  
- **主な原因**  
  - 学習データの誤りや偏り  
  - モデルが不足情報を推測で補完  
  - 知識のない領域で無理に回答

### 2. ハルシネーションを減らす方法
1. **プロンプトの工夫**  
   - 出典を求める（例：「根拠とともに答えてください」）  
   - 「わからない場合は不明と答える」と明示  

2. **追加学習や調整**  
   - 専門データでファインチューニング  
   - **RAG（Retrieval-Augmented Generation）** で外部データを参照  

3. **モデルの選択**  
   - 最新知識を持つモデルを利用  
   - ドメイン特化型モデルを選択  

### 3. ファクトチェックの方法
- **クロスチェック**：複数モデルで回答を比較  
- **外部情報源との照合**：検索・公式文書・論文など  
- **人間による検証**：重要な分野（医療・法律・契約）では必須

### 4. 試験で押さえたいキーワード
- **Human-in-the-loop**：人間による確認が不可欠  
- **RAG**：外部知識を取り込むことで精度向上  
- **対策の三本柱**：プロンプト工夫・追加学習・外部情報活用

## 1. AIの歴史

### エキスパートシステム
- **意味**: 専門家の知識をルールとして組み込み、推論エンジンで解答を導くAI。1980年代に実用化。  

「ルールベース（人が知識を入力）」と「統計学習ベース（データから学ぶ）」の違い

1. ルールベース（Rule-based AI）
知識の獲得方法: 人間の専門家がルールを「手で入力」

2. 統計学習ベース（Data-driven AI）
知識の獲得方法: 大量のデータを使い、統計や機械学習によって自動的にルールを発見

第二次AIブーム → ルールベース型（人がルールを入れる）
第三次AIブーム → 統計学習ベース（データから学習）

### 推論エンジン
- **意味**: 蓄積した知識を使って論理的に結論を導く仕組み。

### 第一次AIブーム
- **意味**: 1950〜60年代。推論・探索を中心とした研究期。

### 第二次AIブーム
- **意味**: 1980年代。エキスパートシステムの商用化が進んだ時期。

### 第三次AIブーム
- **意味**: 2010年代以降。ディープラーニングやビッグデータにより飛躍的発展。

### ディープラーニングの台頭
- **意味**: 多層ニューラルネットワークを活用し、高精度な学習が可能になった流れ。

### ニューラルネットワークの再評価
- **意味**: 過去に停滞していたが、計算資源・データ拡大で再び脚光を浴びた。

### GPUの活用
- **意味**: 行列演算の高速化によりディープラーニングを支えたハードウェア要素。

### ビッグデータの到来
- **意味**: 大量のデータ収集・蓄積がAI学習の基盤となった時代。

### AlphaGo
- **意味**: 囲碁でプロ棋士を破ったAI。ディープラーニング＋強化学習の代表例。  

## 2. 基本用語

### トークナイゼーション
- **意味**: テキストを単語やサブワードに分割する処理。

### 埋め込み表現（Embedding）
- **意味**: 単語や文をベクトルに変換し、意味的な近さを計算できる表現。

### 転移学習
- **意味**: 既存モデルで学習済みの知識を、新しいタスクに応用する学習方法。
- **深掘りメモ**:GPT-2で学んだ「言語理解能力」を、別のタスクに応用
例：質問応答チャットボット

### 微調整（Fine-tuning）
- **意味**: 事前学習モデルを、特定のタスク向けに追加学習させる手法。

### RLHF（人間のフィードバックによる強化学習）
- **意味**: 人間の評価を報酬としてモデルを調整する手法。ChatGPTにも使われている。

### アライメント（Alignment）
- **意味**: AIを人間の価値観や意図に沿うよう調整すること。  
- **深掘りメモ**:  AIは強力な生成能力を持つが、制御されていないと以下の問題が起こることがある
・不適切な発言や差別的表現
・誤情報の生成（ハルシネーション）
・ユーザーの意図に沿わない回答

そこで 「AIの出力を人間の意図に沿うよう制御する」 仕組みとしてアライメントが重要になる

🔹 現代LLMのアライメントの型
1.事前学習モデル＋転移学習
・まず膨大な一般データで事前学習
・基本的な言語理解能力を習得

2.人間フィードバックによる調整（RLHF）
・人間の評価を報酬にしてモデル出力を微調整
・安全で適切な応答に誘導

3.プロンプト設計による制御
・システムプロンプト：モデルの振る舞いを指示
・リファインプロンプト：ユーザー指示を具体化して改善

4.出力後フィルタリング
・不適切な単語や表現を自動でブロック
・モデルのハルシネーションを検知する補助的仕組み

## 3. アルゴリズム

### 勾配降下法（Gradient Descent）
- **意味**: 損失関数の値を最小化するためにパラメータを更新する最適化手法。

### 損失関数（Loss Function）
- **意味**: 予測値と正解の差を数値化する指標。学習の目標となる。

### 活性化関数（Activation Function）
- **意味**: ニューラルネットに非線形性を与える関数。ReLUやSigmoidなど。

### ソフトマックス関数
- **意味**: 出力を確率分布に変換する関数。分類タスクで使用される。

### Attention Mechanism
- **意味**: 入力の重要部分に重みを割り当て、処理を集中させる仕組み。

### Encoder-Decoder構造
- **意味**: 入力をエンコードし、出力をデコードする構造。翻訳モデルなどで利用。


### 自己回帰モデル（Autoregressive Model）
- **意味**: 過去の出力をもとに次の出力を逐次生成するモデル。GPT系列に用いられる。

### Masked Language Model
- **意味**: 文中のマスク部分を予測するモデル。BERTの学習に使われる。

### ビームサーチ（Beam Search）
- **意味**: 複数候補を並行探索し、最適な出力を選択する探索アルゴリズム。
- **深掘りメモ**: 
各ステップで最もスコアの高いトークンを選択する→出力に偏りが出てしまう。
対策：
1.温度調整（Temperature）
2.
Top-k サンプリング: 上位 k 個のトークンからランダムに選ぶ
Top-p（Nucleus）サンプリング:累積確率 p 以下のトークンからランダムに選ぶ

# 生成AIの実務シナリオまとめ

## 1. 文章生成（Text Generation）
- **用途**：文章作成、要約、翻訳、メール作成、レポート作成  
- **利点**：作業時間の短縮、アイデア出し効率化  
- **リスク**：ハルシネーション、バイアス・不適切表現  
- **実務例**：マーケティング文書生成、FAQ応答、議事録自動要約  

## 2. 画像生成（Image Generation）
- **用途**：広告、デザイン、キャラクター作成、アバター作成  
- **利点**：デザイン作業の短縮、少人数でも多様なビジュアル作成  
- **リスク**：著作権問題、倫理リスク  
- **実務例**：広告バナー生成、ゲームキャラクター作成、アイコン生成  

## 3. 音声生成（Voice / Speech）
- **用途**：音声合成、音声翻訳、ナレーション作成  
- **利点**：音声コンテンツ制作コスト削減、声のバリエーション作成  
- **リスク**：肖像権問題、誤情報音声の拡散  
- **実務例**：教育・広告ナレーション、翻訳音声、多言語ボイスチャット  

## 4. コード生成 / プログラミング補助
- **用途**：コード自動生成、バグ修正、ドキュメント作成  
- **利点**：開発速度向上、定型処理の自動化  
- **リスク**：セキュリティ脆弱性、著作権付きコード生成  
- **実務例**：GitHub Copilotでのコード補完、テストコード生成、定型スクリプト作成  

## 5. データ分析・意思決定支援
- **用途**：レポート作成、データ解釈、未来予測  
- **利点**：データ処理効率化、分析結果の自動可視化  
- **リスク**：バイアスによる誤判断、誤統計情報の提示  
- **実務例**：売上データ自動分析、市場動向レポート作成、BIツール連携での洞察提供

**ポイント**  
- AIは自動化を補助するツールであり、**最終判断は人間が行う**  
- ハルシネーション、バイアス、著作権のリスクを理解して運用することが重要

# 生成AIパスポート対策：プロンプト演習まとめ

## 1. プロンプト設計の基本
- **目的を明確にする**  
  例：「商品の説明文を作成する」「要約して3行にまとめる」
- **役割を指定する**  
  例：「あなたは法律の専門家です」「あなたは英語教師です」
- **出力形式を指定する**  
  例：「表形式で」「箇条書きで」「JSON形式で」
- **Few-shot学習**  
  少数の具体例を提示して出力パターンを学習させる

## 2. リファインプロンプト（出力精度を上げる工夫）
- **不明な場合は回答を避ける指示**  
  例：不明な場合は '不明' と答える
- **出典・根拠の提示を要求**  
  例：回答には必ず参考文献やURLを添える
- **文体・トーンの指定**  
  例：丁寧語で説明する／カジュアルで親しみやすく書く
- **段階的指示**  
  例：
  1. 要約する  
  2. キーワードを抽出する  
  3. 表形式でまとめる

## 3. 実務シナリオ別プロンプト例
- **文章生成**  
  例：あなたはマーケティング担当です。以下の商品情報からSNS投稿用の文章を3行で作成してください。
- **画像生成**  
  例：キャラクターを生成してください。条件: 青い服を着たアライグマ、笑顔、背景は森。
- **音声生成**  
  例：以下のテキストをナレーション用の自然な音声に変換してください。声のトーンは落ち着いた女性。
- **コード生成**  
  例：Pythonで指定されたCSVファイルを読み込み、列ごとの平均値を計算する関数を作成してください。
- **データ分析・意思決定支援**  
  例：売上データを元に、過去3ヶ月の売上傾向を簡単にまとめ、今後の戦略を提案してください。

## 4. ポイントまとめ
- 明確で具体的な指示がAIの精度を大きく左右する
- 出力形式・役割・トーンを指定するだけでも精度向上
- リファインプロンプトで回答の正確性・信頼性を上げる
- 段階的指示により複雑タスクを分かりやすく処理可能

# 模擬試験での苦手ポイントまとめ

## 1. 説明責任（Accountability）の定義
- **基本定義**  
  自分の行動や判断に対して、結果やプロセスを説明・責任追及できる状態にあること
- **AI倫理文脈での意味**  
  AIが意思決定に関与した場合に、誰がどのような判断を下したのかを 明確にできること

## 2. ポイント
**意思決定の透明性**
AIの判断や推論過程を追跡・説明できること
**責任の所在**
AIが誤判断をした場合、誰が責任を負うのかを明確化
**説明可能性（Explainability）との関係**
説明責任を果たすためには、AIの判断が人間に理解できる形で説明可能であることが必要

## 3. ポイント
**医療AI**
誤診や副作用リスクが発生した場合、AIの判断プロセスを医師や患者に説明できること
**金融AI**
融資審査AIが否決した場合、理由を顧客に説明できること
**行政AI**
AIが行政判断を補助した場合、決定責任が誰にあるか明確化されていること

## 4. 他の倫理概念との違い
- **公平性（Fairness）**  
  偏りのない判断をすること。説明責任は「判断過程を説明できること」に重点
  - **透明性（Transparency）**  
  AIの仕組みやアルゴリズムを開示すること。説明責任は「判断結果やプロセスに責任を持つこと」に重点
  - **プライバシー**  
  データ保護に関する概念。説明責任とは直接関係ない場合もあるが、判断に使ったデータは説明可能であることが望ましい

説明責任は“AIそのもの”ではなく、AIを利用する組織や人に帰属する
試験では「医療や金融など、人命・社会に影響する判断で問われる」ケースを押さえておくと良い

## 第2章 [生成AI(ジェネレーティブAI)]

### 2-1 [生成AI(ジェネレーティブAI)とは]

**学習目標**
- [生成モデルが誕生してから現在に至るまでに登場してきた様々なモデルの種類と手法を学習する]

#### 学習項目: [生成モデルの誕生]

**定義**

 - 生成モデルはデータの確率分布を学習して新しいサンプル（画像・音声・文章など）を生み出すモデル群の総称。

**詳細キーワード**

| 用語 | 意味・定義 |
|------|------------|
| **[生成AI（ジェネレーティブAI）]** | [新規コンテンツを生成するAI全般。] |
| **[エネルギーベースモデル / ボルツマンマシン]** | [初期の確率的生成モデルの一群（エネルギー関数で確率を定義）] |
| **[自己回帰／潜在変数モデル]** | [生成モデルの代表的アプローチ群。] |

#### 学習項目: [自己回帰モデルとディープラーニング（深層学習）]

**定義**

 - 自己回帰モデルは過去の値（前文脈）に条件付けて次を逐次予測する方式。ディープラーニングは多層ニューラルネットを用いた表現学習の枠組み。

**詳細キーワード**

| 用語 | 意味・定義 |
|------|------------|
| **[自己回帰（autoregressive）]** | [条件付きで次のトークンを順に生成（例：n-gram → RNN → Transformer系の一部）。] |
| **[深層学習（Deep Learning）]** | [多層で高次特徴を学ぶ手法。] |
| **[ボルツマンマシン（関連歴史用語）]** | [確率的な生成モデルで、エネルギーベースの無向グラフィカルモデル。入力と隠れユニットが相互接続され、確率的に状態を更新して学習する。] |

#### 学習項目: [CNN（畳み込みニューラルネットワーク）]

**定義**

 - 画像などの格子状データの局所的特徴を抽出するためのネットワーク構造。

**詳細キーワード**

| 用語 | 意味・定義 |
|------|------------|
| **[畳み込み（Convolution）]** | [フィルタ（カーネル）で局所パターンを検出。] |
| **[フィルタ/カーネル・特徴マップ]** | [抽出された空間特徴の層表現。] |
| **[プーリング]** | [空間次元を縮小して要約する処理。] |

#### 学習項目: [VAE（変分自己符号化器）]

**定義**

 - 入力を潜在空間の確率分布として表現し、そこからサンプリングしてデータを生成する確率的オートエンコーダ。

**詳細キーワード**

| 用語 | 意味・定義 |
|------|------------|
| **[エンコーダ / デコーダ]** | [入力→潜在、潜在→再構成の双方向ネット。] |
| **[潜在ベクトル（latent）]** | [データを圧縮した連続表現。] |
| **[ノイズ／再パラメータ化トリック / KL ダイバージェンス]** | [学習で使う確率的手法。] |

#### 学習項目: [GAN（敵対的生成ネットワーク）]

**定義**

 - 生成器（Generator）と識別器（Discriminator）を競わせることで、高品質なサンプルを生成するフレームワーク。

**詳細キーワード**

| 用語 | 意味・定義 |
|------|------------|
| **[生成器 / 識別器]** | [偽物を作る側と見破る側の二者。] |
| **[敵対的学習（minimax）]** | [両者が競合する最適化。] |
| **[モード崩壊 / 学習不安定性]** | [典型的な課題（改善手法としてWGAN等）。] |

#### 学習項目: [RNN（リカレントニューラルネットワーク）]

**定義**

 - 系列データ（時系列・文章）を扱うため、内部状態を時刻間で伝播するネットワーク。

**詳細キーワード**

| 用語 | 意味・定義 |
|------|------------|
| **[リカレント層 / 隠れ状態]** | [前の情報を次へ引き継ぐメカニズム。] |
| **[BPTT（時間に沿った誤差逆伝播）]** | [系列学習の訓練手法。] |
| **[勾配消失／爆発]** | [長期依存を扱う上での課題。] |

#### 学習項目: [LSTM（長短期記憶）]

**定義**

 - RNNの欠点（長期依存の学習が難しい点）を解決するためのゲート機構付きユニット。

**詳細キーワード**

| 用語 | 意味・定義 |
|------|------------|
| **[入力ゲート／忘却ゲート／出力ゲート]** | [情報の保持・更新を制御する仕組み。] |
| **[セル状態（長期記憶）]** | [長期情報を安定して保持するための内部メモリ。] |

#### 学習項目: [Transformerモデル]

**定義**

 - Attention（自己注意）を中心に、系列を並列に処理できるアーキテクチャ。自然言語処理で画期的な性能を示した。

**詳細キーワード**

| 用語 | 意味・定義 |
|------|------------|
| **[Self-Attention / Multi-Head Attention]** | [入力内トークン間の依存を重み付け計算する層。] |
| **[位置エンコーディング]** | [系列順序情報を埋め込む手法。] |
| **[エンコーダ／デコーダ構造]** | [用途に応じた構成（BERT/GPT 等の派生）。] |

#### 学習項目: [Transformer登場以後の派生モデルの系譜]

**定義**

 - Transformerを起点に発展した各種モデル（GPT 系列、BERT 系列、改良版）とその用途・特徴の系譜。

**詳細キーワード**

| 用語 | 意味・定義 |
|------|------------|
| **[GPTモデル（デコーダのみ）]** | [自己回帰的生成に最適化されたモデル群（GPT-1→2→3→3.5→4等）。] |
| **[BERTモデル（エンコーダのみ）]** | [双方向文脈を学習する事前学習モデル（MLM等）。] |
| **[RoBERTa / ALBERT / T5 / 各種改良版]** | [事前学習手法や効率改善に注力した派生モデル群。] |
