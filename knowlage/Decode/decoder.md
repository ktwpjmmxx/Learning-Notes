# Transformer (Decoder-Only)

## Phase
- 1.Input Embedding 
- 2.Transformer Block(The Core)
- 3.Output Head
- 4.Decoding

## Phase 1: Input Embedding
人間が読めるテキストを、機械が計算可能な「高次元ベクトル」に変換する工程。

### 1. Tokenization
* **処理:** テキストをトークンID（整数）の列に分解。
* **手法:** BPE (Byte Pair Encoding), SentencePiece。
* **例:** `「今日はいい天気」` → `[283, 4920, 11, 583]`

### 2. Embedding Layer
IDをベクトルに変換し、位置情報を付与。
$$Input = TokenEmbedding + PositionalInfo$$
* **Token Embedding:** トークンIDを高次元の実数ベクトルに変換する「辞書引き」の処理。
    * **実体:** `語彙サイズ × 次元数`（例: 32,000 × 4,096）の**重み行列（Embedding Table）**。学習によって獲得される。
    * **仕組み:** トークンIDを行番号として使い、対応する行ベクトルをそのまま取り出す（単なるテーブルルックアップ）。掛け算などの計算は発生しない。
    * **意味:** ベクトルの各次元が何らかの意味的・文法的特徴を（暗黙的に）表現している。例えば「王」と「女王」のベクトルは近く、「犬」と「猫」も近い。
    * **次元数:** モデルサイズによって異なる（例: LLaMA 3 8B → 4,096次元、GPT-4 → 推定12,288次元）。
* **Positional Encoding:** 単語の順番（位置情報）を付与。
    * **主流:** **RoPE (Rotary Positional Embeddings)**。ベクトルを足すのではなく「回転」させることで、相対的な位置関係を学習しやすくする。

> ####  memo：Phase 1における私の解釈
> 
> 全く違う文脈のプロンプトでも、**同じトークンが同じ位置（インデックス）に出現した場合、Phase 1完了時点でのベクトルは「全く同じ数値（完全一致）」**になります。
> 
> * **例①：** `[BOS]`(0) `私`(1) `は`(2) **`木`**(3) `に`(4) `登る`(5)
> * **例②：** `[BOS]`(0) `リンゴ`(1) `が`(2) **`木`**(3) `に`(4) `実る`(5)
> 
> トークンIDが同じで、付与される位置情報（3番目のバーコード）も同じであるため、この時点での「木」の4096次元ベクトルは一言一句同じとなる。
> 
> **全く同じでも問題ない**
> Phase 1で作られるのは、まだ周囲の単語を知らない**「文脈非依存の静的ベクトル」**のため。
> 
> これが次の**Phase 2（Self-Attention）**に入った瞬間、周囲の単語（「登る」や「リンゴ」）と掛け合わされることで、初めて「登る対象としての木」や「果樹としての木」という**「世界に一つだけの動的ベクトル（文脈依存）」**へと変化する。

## Phase 2: Transformerブロック (The Core)
文脈理解と推論の心臓部。このブロックが何層（例: 32層, 96層）も積み重なる。

### 1. Multi-Head Self-Attention（自己注意機構）
文脈（Context）を理解し、単語間の関連度を計算。
* **Q, K, V の生成:** 入力ベクトル × 重み行列 ($W_Q, W_K, W_V$)
    * **Query (Q):** 検索クエリ（私は何を探しているか？）
    * **Key (K):** 索引（私はどんな情報を持っているか？）
    * **Value (V):** 内容（私の実際の中身は何か？）
* **Attention Score:** $Q$ と $K$ の内積。
    $$Score = \frac{Q \cdot K^T}{\sqrt{d_k}}$$
    * **$\sqrt{d_k}$ で割る理由:** 次元数が大きくなるほど内積値が巨大になり、Softmax後の勾配が消えやすくなるため、スケーリングして安定化させる。
* **Softmax:** ScoreをAttention Weight（重み）に変換。各行の合計が1になる確率分布。
    $$Attention\ Weight = \text{softmax}(Score)$$
* **出力:** Attention WeightとVを掛け合わせ、「どのトークンをどれだけ参照するか」を反映した新しいベクトルを生成。
    $$Attention(Q, K, V) = \text{softmax}\!\left(\frac{Q \cdot K^T}{\sqrt{d_k}}\right) V$$
* **Multi-Head化:** 上記のAttention計算を $h$ 個のヘッドで並列実行（例: 32ヘッド）。各ヘッドが異なる観点（構文・意味・指示関係など）を独立して学習し、最後に結合する。

### 2. Causal Masking（因果マスキング）
未来の単語をカンニングしないための処理。
* **処理:** Attention行列の対角線より右上（未来）に $-\infty$ を加算。
* **結果:** Softmax後の確率が $0$ になり、過去の単語のみから次の単語を予測する。

### 3. Feed-Forward Network (FFN)
Attentionで得た情報を知識として定着・変換。
* **構造:** 2つの線形変換と活性化関数で構成。次元を一度大きく広げてから元に戻す。
    $$FFN(x) = \text{Activation}(x W_1 + b_1) W_2 + b_2$$
    * 中間層の次元は通常 $d_{model}$ の **4倍**（例: 4096 → 16,384 → 4096）。
* **主流:** ReLUではなく **SwiGLU** や **GeGLU** などの活性化関数が採用される（Llama 3等）。
* **役割分担:** Self-Attentionが「どのトークンに注目するか（関係性）」を学ぶのに対し、FFNは「そのトークンについて何を知っているか（知識）」を学ぶと解釈される。

### 4. Residual Connection（残差接続）& Layer Normalization
ブロックを深く積み重ねるために不可欠な安定化機構。
* **Residual Connection:** サブレイヤー（AttentionまたはFFN）の入力をそのまま出力に加算する。
    $$x' = x + \text{SubLayer}(x)$$
    * **効果:** 勾配消失を防ぎ、何十層積み重ねても学習が安定する。出力が入力の「差分（修正量）」だけを学べばよくなる。
* **Layer Normalization:** 各トークンのベクトルを正規化し、学習を安定させる。
    * **主流（Pre-LN）:** 現代のモデル（Llama等）はSubLayerに入る**前**に正規化を行う。元論文（Post-LN）より安定して学習できる。
    * **RMSNorm:** Layer Normの簡略版。平均を計算せず二乗平均平方根（RMS）のみで正規化する。LLaMA等で採用。

> #### memo：Phase 2における私の解釈
>
> **1回のブロックで何が起きているか**
>
> 1つのTransformerブロックを通過するたびに、各トークンのベクトルは以下の2段階で更新される。
>
> 1. **Self-Attention:** 「文章中の他のどのトークンを参照すべきか」を計算し、文脈情報をベクトルに混ぜ込む。
> 2. **FFN:** 「そのトークンIDに紐づいた知識・変換」を適用する。
>
> **なぜ何層も積み重ねるのか**
>
> 1層目では「隣の単語との関係」のような浅い特徴しか捉えられない。層を重ねるごとに、より抽象的・長距離の依存関係（「文章全体のテーマ」「文法的な主語と述語の対応」など）を段階的に学習できる。
>
> **各ブロックの処理順（Pre-LN構成）**
>
> `LayerNorm → Self-Attention → Residual加算 → LayerNorm → FFN → Residual加算`
>
> これを $N$ 回繰り返した最後の出力ベクトルが、Phase 3（Output Head）へ渡される。

## Phase 3: 出力層 (Output Head)
ベクトルを単語のスコアに戻す工程。

### 1. Unembedding (Linear Layer)
* **処理:** 最終層のベクトル（例: 4096次元）を **語彙サイズ（例: 50,000次元）** に拡張。
* **Logits (ロジット):** 全単語に対する「次に来るもっともらしさ」の生スコア。確率（0~1）になる前の値。

---

## Phase 4: サンプリング (Decoding)
Logitsを確率に変換し、次の1単語を決定する。

### 1. Temperature（温度パラメータ）
$$Logits' = \frac{Logits}{T}$$
* **$T < 1.0$ (低温):** 確率分布が尖る → 論理的・保守的。
* **$T > 1.0$ (高温):** 確率分布が平坦化 → 創造的・ランダム。

### 2. Softmax
Logitsを確率（合計100%）に正規化。
$$Probability = \frac{e^{x_i}}{\sum e^{x_j}}$$

### 3. フィルタリング (Top-k & Top-p)
低確率なノイズ単語をカットする。
* **Top-k:** 上位 $k$ 個（例: 50個）のみ残す。選択肢が固定。
* **Top-p (Nucleus Sampling):** ★主流
    * 累積確率が $p$（例: 0.9 = 90%）になるまで上位から単語を採用。
    * **特徴:** 自信がある時は候補を絞り、迷った時は候補を広げる（動的制御）。

### 4. 決定 (Selection)
最終候補の中からランダムに1つのトークンを選択し、次の入力へ回す。
