### 1. Multi-Head Attentionの数学的理解

Multi-Head Attention（MHA）は、Self-Attentionを複数の「頭（head）」で並列計算し、異なる観点から文脈情報を捉える仕組み。

#### 基本概念
- 各頭（head）が独立してSelf-Attentionを計算  
- 異なる注意パターンを学習可能  
- 最終的に各頭の出力を結合して次層に渡す

#### 数学的処理の流れ
1. **入力ベクトルの線形変換**
   - `Q_i = X W_i^Q`, `K_i = X W_i^K`, `V_i = X W_i^V`  
   - `i` はhead番号

   - **処理内容**  
  - 入力ベクトル \(X\) を、各headごとに Query (Q)、Key (K)、Value (V) に変換  
  - 線形変換: `Q_i = X W_i^Q, K_i = X W_i^K, V_i = X W_i^V`
- **目的・意図**  
  - 単語ベクトルを「注目する情報(Q)」「注目される情報(K)」「伝達する情報(V)」に分ける  
  - 各headが異なる文脈パターンを学習できるよう情報を分散

2. **スコア計算と正規化**
   - `Attention(Q_i, K_i, V_i) = softmax(Q_i K_i^T / √d_k) V_i`  
   - 各頭ごとに異なる注目先を計算

   - **処理内容**  
  - 各headで `Attention(Q_i, K_i, V_i) = softmax(Q_i K_i^T / √d_k) V_i` を計算  
  - QueryとKeyの内積で関連性（注目度）を計算し、softmaxで正規化
- **目的・意図**  
  - 単語間の「どの単語に注目すべきか」を定量化  
  - 正規化により、注意の重みが0〜1に収まり影響度を適切に調整

3. **頭の結合と線形変換**
   - `MultiHead(X) = Concat(head_1,...,head_h) W^O`  
   - 異なる頭の情報を統合し次層へ

   - **処理内容**  
  - 各headの出力を結合（Concat）し、線形変換 `W^O` を適用  
  - `MultiHead(X) = Concat(head_1,...,head_h) W^O`
- **目的・意図**  
  - 複数headで得た注目パターンを統合  
  - 結合した情報を次層に渡し、文脈理解や生成に活用

#### ポイント
- 複数の注意パターンを同時に学習できる  
- 文脈理解や長距離依存の表現力が向上  
- 計算コストは線形でないため、スケーラビリティの工夫が必要

入力されたプロンプト（例：単語列） をそのまま意味的に理解するわけではなく、
各単語が文章中の他の単語にどれだけ注目すべきか を計算して、文脈に沿ったベクトル表現に変換する処理。

具体的には：
各単語を Query, Key, Value に変換
Query と Key の関連度（どの単語に注目すべきか）を計算
Value を重み付きで合計 → 新しい単語ベクトルを作成
・語同士の関係性を踏まえて文脈情報をベクトル化する処理 が Self-Attention／Multi-Head Attention。

例えると、文章の中で「どの単語が重要か」をそれぞれの観点（head）から見て整理するフィルターのようなもの。

### 2. Encoder-Decoderの違い

Transformerには **Encoder-Decoder構造** と **Decoder単体構造** があり、用途や処理の流れが異なる。

#### 1. Encoder-Decoder構造
- **構成**  
  - **Encoder**：入力文章をベクトル化して文脈情報を抽出  
  - **Decoder**：Encoderの出力を参照しながら出力文章を生成
- **用途**  
  - 翻訳、要約、質問応答など「入力文章を別の文章に変換するタスク」
- **特徴**  
  - Encoderが入力全体の情報を理解  
  - Decoderは逐次生成を行いながら、Encoderの情報を参照して出力

#### 2. Decoder単体構造（GPT系）
- **構成**  
  - Encoderを持たず、Decoderのみで自己回帰型生成  
  - 過去の出力トークンを参照して次の単語を生成
- **用途**  
  - 文書生成、チャットボット、文章補完など
- **特徴**  
  - 入力プロンプトから直接生成  
  - マルチヘッドAttentionで過去トークンとの依存関係を計算

#### ポイントまとめ
- **Encoder-Decoder**：入力 → 変換 → 出力（翻訳や要約向き）  
- **Decoder単体**：入力 → 逐次生成（文章生成向き）  
- GPTはこの **Decoder単体構造** を採用している

### 1. Self-Attentionの計算複雑度

#### 1-1. 基本の仕組み
- Self-Attentionは、入力された全トークン同士の関連度を計算する仕組み
- 各トークンが「全てのトークンに注目」するため、**全結合的な計算** が必要

#### 1-2. 計算量の増え方
- トークン数を **N**、ベクトル次元を **d** とすると
  - Attentionスコア計算: `O(N^2 * d)`
  - Softmax正規化: `O(N^2)`
- 結果、**全体の計算量は O(N^2)** に比例して増加する

### 補足: Attentionスコア計算とSoftmax正規化の目的

#### 1. Attentionスコア計算
- 各トークン同士の「関連度」を数値化する処理
- **Query (Q)** と **Key (K)** の内積で求める  
  - 大きい値 → 強く関連している  
  - 小さい値 → 関係が弱い  
- 例: 「The cat sat on the mat」の中で  
  - "cat" の Query と "sat" の Key を比較すると大きめのスコア  
  - "cat" の Query と "the" の Key だと比較的小さいスコア

#### 2. Softmax正規化
- スコアをそのまま使うと値の大小に偏りが出すぎるため、**確率分布**に変換する
- すべての関連度を 0〜1 の範囲に収めて合計を 1 にする
- これにより「どの単語にどの程度注意を向けるか」が確率的に表現される  
  - 例: "cat" → { "sat": 0.6, "on": 0.2, "the": 0.1, "mat": 0.1 }
- この重みを使って **Value (V)** を加重平均し、文脈を反映した表現を得る

### Q, K, V とは？

Transformer の Self-Attention では、入力ベクトルから **3種類のベクトル** を作ります。

1. **Query (Q)**  
   - 「どの単語に注目したいか」を表すベクトル  
   - 例: "cat" が「自分に関係する単語はどれ？」と問いかけるときの視点

2. **Key (K)**  
   - 「自分がどんな特徴を持っているか」を表すベクトル  
   - 例: "sat" が「私は動作を表す単語だよ」と自己紹介するラベル

3. **Value (V)**  
   - 実際に伝える情報（特徴ベクトル）  
   - 最終的に重み付き平均をとる対象  
   - 例: "sat" の意味や文脈情報そのもの

---

### Attention スコアと確率分布

1. **スコア計算**  
   - 各トークン間の関連度は  
     \[
     \text{score}(Q, K) = Q \cdot K^T
     \]  
     で求める（内積）。  
   - "cat" (Q) と "sat" (K) のスコアが高ければ「関連が強い」と判断。

2. **Softmax で正規化**  
   - スコアの合計を 1 に揃えることで「確率分布」に変換する。  
   - 確率分布とは「全体の中で、どこにどれだけの割合で注意を配るか」を示す。  
   - 例:  
     ```
     "cat" の Query に対する Attention 分布
     { "sat": 0.6, "on": 0.2, "the": 0.1, "mat": 0.1 }
     ```

3. **Value の加重平均**  
   - 上記の確率を重みにして Value を混ぜ合わせる。  
   - これにより、"cat" は「自分が一番関係ある 'sat' を強めに取り込みつつ、他の単語も少し反映した文脈表現」を得る。
  
- **Q** = 注目する視点  
- **K** = 注目されるための鍵  
- **V** = 実際に受け取る情報  
- **Softmax確率分布** = どの単語にどの程度注意を分配するかを整理する仕組み


#### 1-3. なぜ問題になるのか
- 短文なら問題ないが、長文になると急激にコストが増える
  - 例: 文章が2倍長くなると、Attention計算は **4倍** に膨れ上がる
- メモリ消費量も同じく `O(N^2)` で増加するため、長文処理や大規模モデルでボトルネックになる

### Self-Attention の計算フロー（数式ベース）

#### 1. 入力の埋め込み
入力文の各トークンはベクトルに変換される（例: "The cat sat" → それぞれの単語ベクトル）。

#### 2. Q, K, V の生成
各入力ベクトルに対して **重み行列 W** を掛けて、  
- Query: \( Q = XW_Q \)  
- Key: \( K = XW_K \)  
- Value: \( V = XW_V \)  
を作成する。  
（Q, K, V はすべて同じ入力 X から派生するが、異なる特徴空間を持つ）

> **補足（推論フェーズでの重みについて）**  
> 学習段階でこれらの重み行列 \(W_Q, W_K, W_V\) はすでに最適化されて固定されている。  
> 例えば GPT-2 では 1,600 次元のベクトル空間を使い、**すべての入力トークンに対して同じ重み行列**を適用する。  
> そのため推論時には「学習済みのパラメータを使って Q, K, V を生成する」だけであり、新たに重みを更新することはない。

#### 3. スコア計算
あるトークンの Q と、他すべてのトークンの K を内積してスコアを得る：  
\[
\text{score}(Q_i, K_j) = Q_i \cdot K_j^T
\]  
→「トークン i が、トークン j にどれだけ関連しているか」を表す。

#### 4. スケーリングと正規化
スコアは大きくなりすぎるので、ベクトルの次元 \(d_k\) で割る：  
\[
\text{scaled\_score} = \frac{QK^T}{\sqrt{d_k}}
\]  

その後 **Softmax** を使って確率分布に変換：  
\[
\alpha_{ij} = \text{softmax}(\text{scaled\_score}_{ij})
\]  
ここで \(\alpha_{ij}\) は「トークン i がトークン j にどれだけ注意を払うか」の割合。

#### 5. Value の加重和
最終的な出力ベクトルは、Value を確率で加重平均したもの：  
\[
Z_i = \sum_j \alpha_{ij} V_j
\]  

> **補足（この時点で各トークンはどうなっているか）**  
> - トークン i の出力ベクトル \(Z_i\) は、**自分自身の情報だけでなく他のトークンの情報も混ざった状態**になる。  
> - 例えば "The cat sat" の "cat" に対応する \(Z_{\text{cat}}\) は、  
>   「前後の 'The' や 'sat' にどれだけ注目したか」を反映して Value を重み付け合成したベクトルになる。  
> - これにより、**文脈を理解した "cat" の表現**が得られる。  
>   つまり最初は孤立した単語ベクトルだったものが、Self-Attention を通して「文全体における cat」という意味を持つように変換される。

### 直感的なまとめ
- **Q** = 「私はどこに注目したい？」  
- **K** = 「私はこんな特徴を持ってるよ」  
- **V** = 「実際に持っている情報はこれ」  
- **Softmax確率分布** = 「注目の割合を決める」  
- **加重和** = 「その割合で情報を混ぜる」

### Multi-Head Attention の概要

Self-Attention は 1 回の「注目計算」で文脈を捉える仕組みだが、  
実際には **複数の視点（head）を並列に動かす**ことでより豊かな表現を得られる。  
これが **Multi-Head Attention**。

---

#### 1. 複数の Q, K, V 空間を作る
- Self-Attention のときと同じように、入力 X から Q, K, V を作る。  
- ただし Multi-Head では **head ごとに異なる重み行列** \(W_Q^{(h)}, W_K^{(h)}, W_V^{(h)}\) を持つ。  
- これにより、同じ入力でも **head ごとに異なる観点で関係性を学習**できる。

---

#### 2. 各 head で Self-Attention を計算
- 各 head が独立に Self-Attention を計算し、出力ベクトル \(Z^{(h)}\) を得る。  
- 例えば "The cat sat" なら、ある head は「主語と動詞の関係」に注目し、  
  別の head は「冠詞と名詞の結びつき」に注目する、といった多様な視点が可能。

---

#### 3. 出力を結合し、線形変換
- すべての head の出力を結合（concat）して、最終的に線形変換する：  
\[
Z = \text{Concat}(Z^{(1)}, Z^{(2)}, \dots, Z^{(h)})W_O
\]  
- これにより「複数の視点から抽出した文脈情報」を統合して次の層に渡す。

---

### 直感的なまとめ
- **Single-Head Attention** → 1 つの視点で文脈を捉える  
- **Multi-Head Attention** → 複数の視点で「並列」に文脈を理解し、それらを統合  
- 結果として、モデルは **文法的関係・意味的な関連・長距離依存** などを同時に学習できる

> GPT 系では Multi-Head Attention がスタックされており、各層ごとに複雑な文脈理解を深めていく。

### なぜ複数の視点（Multi-Head）が必要か？

1 つの Self-Attention（Single-Head）は、入力文の中で「どこに注目すべきか」を学習できる。  
しかし自然言語は同時に **複数の関係性** を持つため、単一の視点だけでは不十分。

---

#### 例：「The cat sat on the mat」

- **Head 1（文法的関係に注目）**  
  - "cat"（主語）が "sat"（動詞）と強く結びつく。  
  - 主語・述語の構造を捉える。  

- **Head 2（意味的関係に注目）**  
  - "mat" が "sat" と関係する。  
  - 「どこに座ったのか」という場所の情報を捉える。  

- **Head 3（長距離依存に注目）**  
  - "The" と "cat" を結びつけて「名詞句」を理解する。  

---

#### 直感的なまとめ
- **Single-Head**：1つの関係しか見られない（例：主語と動詞のつながりだけ）。  
- **Multi-Head**：複数の関係を同時に学習（文法・意味・修飾・長距離依存など）。  
- その結果、モデルは文をより豊かに、正確に理解できる。

> 複数の視点を並列で処理するからこそ、GPT のような大規模言語モデルは自然な文章を生成できる。

### 計算複雑度とスケーラビリティ

#### 1. Self-Attention の計算コスト
- Self-Attention では、**すべてのトークン同士の関係**を計算する必要がある。  
- トークン数を \(n\)、ベクトルの次元を \(d\) とすると、計算量は：  
\[
O(n^2 \cdot d)
\]  
- \(n^2\) の部分は「全トークンの組み合わせ」に由来。  
- このため、トークン数が増えるほど計算コストとメモリ使用量が急増する。

---

#### 2. 実際の影響
- 短い文（例：20トークン程度）では問題ないが、  
  1000 トークンを超える長文になると計算量が膨大に。  
- GPU メモリ使用量も増え、バッチサイズやモデルサイズに制約がかかる。

---

#### 3. スケーラビリティへの工夫
- **制限付き Attention**  
  - 近傍のトークンだけを対象に計算し、遠い依存関係を省略。  
- **効率化手法（Sparse Attention, Linear Attention など）**  
  - 計算を近似して \(O(n)\) や \(O(n \log n)\) に削減。  
- **分割処理**  
  - 長文を複数チャンクに分けて処理し、後で統合する。  

---

### 直感的なまとめ
- Self-Attention は強力だが、**計算量が二次関数的に増える**ためそのままではスケールしにくい。  
- GPT-3 や GPT-4 など大規模モデルでは、効率的な Attention 実装やハードウェア最適化が欠かせない。  
- 今後の研究テーマの一つは「長文を効率的に扱う Attention」の実現。
