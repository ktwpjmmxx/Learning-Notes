# ハイブリッド型要約システム 使い方ガイド

## 📊 最適な文数の決め方

### 1. 入力文章の長さで判断

| 入力の文数 | 推奨抽出文数 | 圧縮率の目安 |
|-----------|-------------|-------------|
| 3-5文 | 2文 | 40-60% |
| 6-10文 | 3-4文 | 30-50% |
| 11-20文 | 4-6文 | 25-40% |
| 21文以上 | 6-8文 | 20-35% |

**基本ルール**: 元の文数の**30-50%**を目安に

---

### 2. 用途で判断

#### 📱 SNS投稿用 (Twitter/X など)
- **文数: 1-2文**
- 極限まで簡潔に

#### 📧 メール/チャット用
- **文数: 2-3文**
- 要点を素早く伝える

#### 📄 レポート要旨
- **文数: 3-5文**
- 全体像を把握できる程度

#### 📚 プレゼン資料
- **文数: 4-6文**
- 詳細な要約が必要

---

### 3. 内容の複雑さで判断

#### シンプルな内容
- **文数: 少なめ(2-3文)**
- 例: 単一トピックのニュース記事

#### 複雑な内容
- **文数: 多め(4-6文)**
- 例: 多面的な議論、複数の論点

---

## 🎨 スタイルの使い分け

### 📝 自然な文章を選ぶべき場合

✅ **こんな時に使う:**
- 報告書やメール本文
- プレゼンのスライド説明
- ブログ記事の要約
- ナラティブ(物語性)が重要
- 流れや因果関係を示したい
- フォーマルな文書

**例: ビジネスメール**
```
近年、リモートワークの普及により働き方が変化しています。
また、柔軟な働き方が可能になった一方で、課題も指摘されて
います。そして、今後は生産性との両立が求められています。
```

---

### 📋 箇条書きを選ぶべき場合

✅ **こんな時に使う:**
- プレゼンのスライド(キーポイント)
- 会議の議事録
- タスクリスト
- 複数の独立した論点
- スキャン性(流し読み)が重要
- 比較・対照が目的

**例: プレゼンスライド**
```
• リモートワークの普及により働き方が変化
• 柔軟な働き方と課題が並存
• 今後は生産性との両立が必要
```

---

## 🎯 実践的な判断フローチャート

```
文章を要約したい
    ↓
Q1: 読み手は流し読みする?
    YES → 箇条書き
    NO → ↓
    
Q2: 因果関係や流れが重要?
    YES → 自然な文章
    NO → ↓
    
Q3: 複数の独立したポイント?
    YES → 箇条書き
    NO → 自然な文章
```

## 💡 具体例で比較

### 例文: リモートワークの文章(280文字、5文)

#### パターン1: 文数2 + 自然な文章
```
近年、リモートワークの普及により、働き方は大きく変化して
います。そして、今後は、テクノロジーを活用しながら、働き
やすさと生産性を両立させる仕組みづくりが求められています。
```
**用途**: Twitter投稿、短いメール

---

#### パターン2: 文数3 + 自然な文章
```
近年、リモートワークの普及により、働き方は大きく変化して
います。また、通勤時間の削減や柔軟なスケジュール管理が可能
になった一方で、コミュニケーション不足や孤独感といった課題も
指摘されています。そして、今後は、テクノロジーを活用しながら、
働きやすさと生産性を両立させる仕組みづくりが求められています。
```
**用途**: レポート要旨、標準的なメール

---

#### パターン3: 文数3 + 箇条書き
```
• 近年、リモートワークの普及により、働き方は大きく変化して
  います
• 通勤時間の削減や柔軟なスケジュール管理が可能になった一方で、
  コミュニケーション不足や孤独感といった課題も指摘されています
• 今後は、テクノロジーを活用しながら、働きやすさと生産性を
  両立させる仕組みづくりが求められています
```
**用途**: プレゼン資料、議事録

## 🔧 調整のコツ

### 文数を決める時の考え方

1. **少なすぎる** → 情報が抜け落ちる
   - 解決: +1文増やす

2. **多すぎる** → 元の文章と変わらない
   - 解決: -1文減らす

3. **ちょうど良い** → 要点を押さえつつ簡潔
   - **元の40-60%が目安**
