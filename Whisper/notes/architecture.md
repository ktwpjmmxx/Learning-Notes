# Whisperアーキテクチャ

## 概要

WhisperはOpenAIが開発した音声認識モデルで、TransformerベースのEncoder-Decoderアーキテクチャを採用しています。68万時間以上の多言語音声データで訓練されており、高精度な音声認識と翻訳を実現しています。

## 全体構造

Whisperは大きく分けて以下の2つのコンポーネントで構成されています:

1. **Encoder（エンコーダー）**: 音声をベクトル表現に変換
2. **Decoder（デコーダー）**: ベクトル表現からテキストを生成

```
音声入力 → [Encoder] → 音声特徴ベクトル → [Decoder] → テキスト出力
```

## Encoder（エンコーダー）

### 役割
音声信号を機械学習モデルが処理できる数値表現（ベクトル）に変換します。

### 処理の流れ

1. **音声の前処理**
   - 音声を16kHzのサンプリングレートに統一
   - 30秒のチャンクに分割
   - メルスペクトログラムに変換（80チャンネル）

2. **Transformerエンコーダー**
   - メルスペクトログラムを入力として受け取る
   - 複数のTransformerブロックで処理
   - 自己注意機構（Self-Attention）により、音声の特徴を抽出
   - 位置情報を保持しながら音声全体のコンテキストを理解

### 通常のスペクトログラムについて
音声→「時間 × 周波数」の表にしたもの。
もともと音声は「波形（time domain）」だが、そのままでは「どんな周波数が含まれているか」が分かりにくい。
そこで フーリエ変換（Fourier Transform） を使って「周波数成分」に分解する。

### 仕組みの流れについて
1. **音声波形**
 - ただの振幅の時間変化。ギザギザの線（オシロスコープで見る波）。

2.**短時間フーリエ変換 (STFT)**
 - 音声を「短い区間（窓）」に分割して、その部分ごとにフーリエ変換をかける。
 - これで「時間ごとの周波数の強さ」が分かる。

3.**スペクトログラム生成**
 - 横軸：時間
 - 縦軸：周波数
 - 色や明るさ：その周波数成分の強さ（パワー）


### メルスペクトログラムとは
音声を周波数成分に分解し、人間の聴覚特性に合わせて変換したもの。画像のように扱うことができ、CNNやTransformerでの処理が可能になります。

## Decoder（デコーダー）

### 役割
エンコーダーが生成した音声特徴ベクトルから、実際のテキストを生成します。

### 処理の流れ

1. **特殊トークンの処理**
   - `<|startoftranscript|>`: 文字起こし開始を示す
   - `<|language|>`: 言語指定（例: `<|ja|>`, `<|en|>`）
   - `<|task|>`: タスク指定（transcribe or translate）
   - `<|notimestamps|>`: タイムスタンプなしを指定

2. **自己回帰的なテキスト生成**
   - 1トークンずつ順番にテキストを生成
   - 前に生成されたトークンを参照しながら次のトークンを予測
   - `<|endoftext|>` トークンで終了

3. **Cross-Attention（交差注意機構）**
   - デコーダーがエンコーダーの出力を参照
   - 音声のどの部分に注目すべきかを学習
   - 音声とテキストの対応関係を確立

## Transformerの仕組み

### Self-Attention（自己注意機構）

入力シーケンス内の各要素が、他のすべての要素との関係性を学習する仕組みです。

**Encoderでの役割**:
- 音声のどの部分が重要かを判断
- 時間的に離れた音声特徴の関係を捉える
- 例: 「こんにちは」という発話全体のコンテキストを理解

**Decoderでの役割**:
- 既に生成されたテキストの文脈を理解
- 次に来るべき単語を予測

### Multi-Head Attention（マルチヘッドアテンション）

複数の異なる注意機構を並列に実行することで、様々な観点から情報を抽出します。

- 8つまたは16つのヘッドを使用
- 各ヘッドが異なる特徴（音韻、韻律、意味など）に注目
- 最終的にすべてのヘッドの情報を統合

## モデルサイズ

Whisperは5つのモデルサイズが提供されています:

| モデル | パラメータ数 | 英語専用 | 多言語 | 必要VRAM | 相対速度 |
|--------|-------------|----------|--------|----------|----------|
| tiny   | 39M         | ✓        | ✓      | ~1GB     | ~32x     |
| base   | 74M         | ✓        | ✓      | ~1GB     | ~16x     |
| small  | 244M        | ✓        | ✓      | ~2GB     | ~6x      |
| medium | 769M        | ✓        | ✓      | ~5GB     | ~2x      |
| large  | 1550M       | ✗        | ✓      | ~10GB    | 1x       |

### モデル選択の指針

- **tiny/base**: リアルタイム処理、リソース制限がある場合
- **small**: バランス型、多くのユースケースに適用可能
- **medium**: 高精度が必要だがリソースに制限がある場合
- **large**: 最高精度が必要な場合（推論時間は長い）

## 訓練データ

Whisperは以下のような大規模データで訓練されています:

- **データ量**: 68万時間の音声データ
- **言語**: 99言語をカバー
- **データソース**: インターネット上の多様な音声データ
- **多様性**: 様々なアクセント、ノイズ環境、話者を含む

この大規模な訓練により、事前学習済みモデルとして高い汎化性能を持っています。

## Whisperの特徴的な設計

### 1. マルチタスク学習

単一モデルで複数のタスクを実行可能:
- 音声認識（transcription）
- 音声翻訳（translation）
- 言語識別（language detection）
- タイムスタンプ生成

### 2. ゼロショット性能

特定のドメインでファインチューニングしなくても、様々な環境で高精度な認識が可能です。

### 3. ノイズ耐性

実世界の多様なノイズ環境で訓練されているため、雑音が多い環境でも安定した性能を発揮します。

## 推論プロセスの流れ

1. 音声ファイルを読み込み
2. 16kHz、30秒チャンクに前処理
3. メルスペクトログラムに変換
4. Encoderで音声特徴を抽出
5. 特殊トークンで言語とタスクを指定
6. Decoderがテキストを自己回帰的に生成
7. 終了トークンまで生成を繰り返し

## 実装上の注意点

### メモリ管理
- モデルサイズに応じたVRAM確保が必要
- バッチ処理時はメモリ使用量が増加
- 長時間音声は自動的にチャンク分割される

### 精度向上のヒント
- 音声品質の向上（ノイズ除去、正規化）
- 適切なモデルサイズの選択
- 言語指定の明示化
- タイムスタンプ生成の有無の選択

### パフォーマンス最適化
- GPU利用による高速化
- FP16（半精度浮動小数点）による推論高速化
- バッチ処理による効率化

## まとめ

Whisperは、Transformer Encoder-Decoderアーキテクチャを基盤とし、大規模マルチタスク学習により高精度な音声認識を実現しています。エンコーダーで音声特徴を抽出し、デコーダーでテキストを生成する、というシンプルながら強力な設計が特徴です。
